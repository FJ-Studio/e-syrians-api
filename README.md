# E-SYRIANS API

The backend API for e-Syrians, a community platform and census tool for Syrian citizens. It powers peer-to-peer identity verification, demographic polling with audience targeting, violation reporting, and census data collection.

The API serves a Next.js web app and a React Native mobile app.

## Tech Stack

Built with PHP 8.4+ and Laravel 13, using Sanctum for API authentication, Socialite for Google OAuth, Spatie Permission for role management, and Spatie Translatable for multilingual support (Arabic, English, Kurdish). Files are stored on AWS S3 and emails are sent via Resend.

## Features

**Authentication and Security** — Email/password registration, Google OAuth, two-factor authentication (TOTP with recovery codes), email verification, and password reset flows. All sensitive PII is stored with dual encryption (encrypted + hashed columns).

**Identity Verification** — A peer-to-peer verification system where users verify each other's identity. Configurable thresholds control how many verifiers are needed and what ratio is required. Certain profile changes (email, phone, national ID) automatically revoke verification status.

**Polling** — Create polls with demographic audience targeting, multiple choice options with configurable max selections, community-contributed options, upvote/downvote reactions, and privacy controls. Only verified users can vote.

**Violation Reporting** — Users can report violations with categorization, file attachments, and status tracking. The community can react to violations.

**Census and Statistics** — Platform-wide demographic statistics covering gender, age, hometown, current country, ethnicity, and religion. Data is cached for performance.

## Didit identity verification sandbox

This pilot is separate from peer verification. It displays **$3.00 USD** per individual verification but does not collect payment. Each allowlisted account can claim one free test credit. An unused credit can be gifted once, using a 30-minute, single-use code generated by the recipient. The sender cannot view the recipient's session or outcome.

Admins can open an allowlisted test account in **Filament → Users** and select **Grant sandbox verification credit**. Each grant adds one account-bound credit without consuming the recipient's free claim. The grant records the admin and an internal reason; the recipient sees the credit but not the note. A grant does not verify the account or bypass Didit.

1. Create or select a **sandbox-mode** Didit application and an individual (KYC) document-verification workflow. Use that workflow's ID and a [scoped API key](https://docs.didit.me/console/api-keys) with session read/write restricted to the workflow; media access isn't needed. Only use Didit's [sandbox test data](https://docs.didit.me/integration/sandbox-testing), never a real ID or selfie.
2. Point the API and both clients at your local test environment. In the API's untracked environment settings, set `IDENTITY_SANDBOX_ENABLED=true`, `IDENTITY_SANDBOX_TEST_USERS` to the comma-separated UUIDs of your synthetic accounts, and configure `DIDIT_SANDBOX_API_KEY` and `DIDIT_SANDBOX_WORKFLOW_ID`. Keep the key server-side. Run `php artisan migrate` against the **local** test database.
3. Set `NEXT_PUBLIC_IDENTITY_SANDBOX_ENABLED=true` for local Next.js and/or `EXPO_PUBLIC_IDENTITY_SANDBOX_ENABLED=true` for local Expo, then restart the corresponding dev server. Open **Account → Verifications → Identity verification sandbox**.
4. Claim a test credit and use it, or generate a gift request code from a second test account and paste it as the sender. As the recipient, refresh credits and start the test. After completing the hosted Didit flow, return to E-Syrians and select **Check result**. The API fetches the decision from Didit; it does not trust a redirect or store the report or its document images.

The API refuses to run this feature in production. Every session includes a sandbox-only scenario (`approve` by default, or `decline_document_expired`). No payments, webhooks, public rollout, or change to the existing verification badge are part of this pilot.

## Getting Started

### Prerequisites

- PHP 8.4+
- Composer
- SQLite (for local development and testing)

### Installation

```bash
git clone git@github.com:FJ-Studio/e-syrians-api.git
cd e-syrians-api
composer install
cp .env.example .env
php artisan key:generate
php artisan migrate
```

### Running the Development Server

```bash
composer dev
```

This starts the Laravel server, queue worker, log viewer, and Vite dev server concurrently.

### Running Tests

```bash
php artisan test
```

## Code Quality

This project enforces strict code quality standards through automated tooling. All checks run on every commit via GrumPHP pre-commit hooks, and again in CI on every pull request.

**Laravel Pint** — PSR-12 formatting with custom rules. Run `./vendor/bin/pint` to format your code.

**PHPStan Level 5** — Static analysis via Larastan. Run `./vendor/bin/phpstan analyse` to check for errors.

**Pest** — Test framework. All new features and bug fixes should include tests.

**Conventional Commits** — All commit messages must follow the format `type: description` where type is one of: `feat`, `fix`, `refactor`, `chore`, `style`, `docs`, `test`.

**Git Blacklist** — Debug statements (`dd()`, `dump()`, `var_dump()`, `die()`, `exit;`) are blocked from being committed.

When you run `composer install`, GrumPHP automatically registers the pre-commit hook. No extra setup is needed.
